# 投资词典 GSC 索引异常诊断

日期：2026-11-20
数据来源：Google Search Console「网页索引编制」报告，逐个原因下钻抓取全量 URL 清单（非抽样）
快照日期：页面显示「上次更新日期：2026/11/16」

---

## 一句话结论

**这不是一个异常，是四个独立问题叠在一起，而且其中三个不是新毛病。**

真正需要动内容的只有一个（433 条抓了不给索引），另外三个是历史包袱和操作待办。现在最不该做的是「因为只有 252 条索引就慌着改 1000 个页面」——数据快照还是 11/16 的，早于 sitemap 提交。

## 问题一｜634 条「网页会自动重定向」——100% 是旧地址，不用改代码

把 634 条全部拉下来逐条判断：**634 条 URL 全部以 `.html` 结尾**，一条例外都没有。

示例：

- `https://dictionary.mangofolio.com/terms/割肉（亏损卖出）.html`
- `https://dictionary.mangofolio.com/terms/五险一金.html`
- `https://dictionary.mangofolio.com/terms/技术分析.html`

**成因**：站点开启 `cleanUrls` 之前，词条页的真实地址带 `.html` 后缀。Google 在那段时间抓了一批，记在库里。现在这些地址被 308 永久重定向到无后缀的规范地址。

**实测确认**：

```
/terms/货币.html  → HTTP 308 → /terms/货币   （200 OK）
/terms/货币/      → HTTP 308 → /terms/货币   （200 OK）
/terms/货币       → HTTP 200 OK
```

**要不要紧**：不要紧。308 与 301 同属永久重定向，权重会传递到新地址。Google 会逐步把旧地址从索引里清掉。

**抓取日期说明一切**：这 634 条的抓取时间集中在 11 月 13–14 日，全部早于 11 月 18 日提交 sitemap。

**要做的事**：不需要改代码。在 GSC 该原因页点「验证修正情况」，让 Google 重新评估这批。它会自然消失。

## 问题二｜446 条「已抓取 - 尚未编入索引」——这个才是真问题

446 条里 **420 条是规范地址**（不是旧 `.html` 地址），26 条是 `.html` 变体。也就是说：Google 抓了正式的词条页，看完之后决定**不给索引**。

这是唯一需要动内容的项。

### 反直觉的发现：不是「内容太薄」

把 420 条对应到本地词条文件，逐页算正文可见字数（去掉脚本、样式、标签）：

| | 未编入索引的 417 条 | 全站 1,141 条 |
|---|---|---|
| 字数中位 | **1,255** | 1,180 |
| 均值 | 1,417 | — |
| P25 / P75 | 1,099 / 1,642 | — |
| < 1,200 字占比 | 44% | — |
| < 1,500 字占比 | 71% | 86% |
| < 800 字占比 | **0%** | — |

**未索引的这批比全站平均还厚一点。** 所以「页面内容太短才不给索引」这个解释不成立。如果继续往「把每页写长」的方向投入，是打偏了。

### 那 Google 在挑什么

结合已有的三项站内审计数据（2026-11-18）：

- 94% 的标题是同一句式「XXX是什么意思？小白也能看懂的理财术语解释」（1,068 / 1,141）
- 92% 的描述用了同一模板
- 60% 的描述里不含词条名
- 页面结构高度统一：一句话卡片 + 4 张故事卡

这是程序化生成内容的典型特征。Google 对这类页面的处理方式是：抓取、识别模式、只保留其中一部分进索引。

**判断：不是「不够长」，是「不够不一样」。**

### 还有一个更硬的原因：抓取预算

把 433 条抓过但未索引的词条，按它们在词库中的顺序定位：

| 词库分段 | 未索引条数 |
|---|---|
| 第 1 段（1–287） | 170 |
| 第 2 段（288–574） | 154 |
| 第 3 段（575–860） | 109 |
| 第 4 段（861–1147） | **0** |

**最后 287 条，一条都没被抓过。**

抓取是按词库顺序推进的，走到 860 条左右就停了。这说明 Google 给的抓取预算不足以覆盖 1,147 个页面，而不是后 287 条页面有什么毛病。

**推论**：新站权重不足时，Google 会限流抓取。sitemap 11-18 才提交，这批大概率在后续轮次才会被爬。

## 执行记录（2026-11-20 已完成）

19 个 404 已全部修完并线上验收，**19/19 通过**（原地址经重定向链最终返回 200）。

### 做了什么

| 项 | 内容 |
|---|---|
| `vercel.json` | 新增 **30 条** 301 规则，覆盖全部 19 个 404 原始地址 |
| 站内坏链 | 14 处 `href` + 2 处 `canonical` 里含斜杠的 slug 改为实际路径（只改 URL，标题与正文文字不动） |
| 根因 | 词条改名后旧 slug 没有留跳转；另有 16 个词条的 `dictionary.json` slug 含斜杠 `/`，而磁盘文件名用的是下划线 `_`，导致 sitemap/canonical 指向 404 |

### 三个踩到的坑（都已修）

**1. 中文 `source` 匹配不到。** Vercel 的 `redirects.source` 按**原始编码路径**匹配，写成未编码中文一律不生效（`/terms/CPI` 这种纯 ASCII 才成功）。全部改为 `encodeURIComponent` 形式后恢复。

**2. 前缀通配造成 308 死循环。** 「茅指数 / 宁组合」原先用 `/terms/茅指数(.*)` 通配，把**正确地址** `/terms/茅指数 _ 宁组合` 也重定向到了它自己，形成无限 308。而这个 URL 就在 sitemap 里，Google 抓到会记成重定向错误。已改为精确匹配旧的多段地址。

**3. `index.html#第X篇` 的真实形态是 `%2523`（双编码）。** 原规则 `/index.html%23(.*)` 匹配不到，补了 `/index.html%2523(.*)`。

### 验收方式

- 19 个 404 原始地址逐条跟随重定向，全部落到 200
- 回归抽检 22 条正常词条 URL（含带空格、带括号、带斜杠下划线的边界样本），全部 200
- `vercel.json` 做了自匹配检查，无剩余「重定向到自己」的规则

### 剩下要你做的

进 GSC → 编制索引 → 「网页会自动重定向」，点一次「**验证修正情况**」，让 Google 重新评估那 634 条旧 `.html` 地址和这 19 条。

## 补充：canonical 审计（2026-11-20 晚）

GSC 帮助文本里有一句容易被忽略的话：「**带有重定向的规范 URL 可以被索引**」。意思是：canonical 或 sitemap 指向的地址如果自己会跳转，Google 就认不准哪个才是正式页面。顺手把全站 1147 个词条页的 canonical 审了一遍。

| 情况 | 数量 | 说明 |
|---|---|---|
| canonical 正确 | 1,133 | — |
| 指向旧域名 `invest-dictionary.mangofolio.com` | **10** | 该域名已下线，返回 **502**；`og:url` 与 JSON-LD `url` 同样是旧域名 |
| canonical 含真实斜杠 | **4** | 磁盘文件名是下划线，canonical 写的是斜杠 → 分别落到 **404**（金融债）和 **308**（货币供应量 / 转债下修 / 策略指数） |
| 无 canonical | 0 | — |

14 处已全部改为与 sitemap 一致的正式地址，线上逐个验证通过。`web/terms_md` 里 10 个 md 的 `source` 字段同步修正。

**sitemap 侧是干净的**：1153 条 URL 并发实测，全部直接返回 200，没有一条重定向。也就是说「重定向的规范 URL」这个坑只出现在 canonical 上，不在 sitemap 上。
