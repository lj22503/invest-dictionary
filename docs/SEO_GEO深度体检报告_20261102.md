## 二、🔴 高优先级问题（P0，直接影响收录与 AI 引用）

### P0-1 robots.txt 尾部混入「（内容由AI生成，仅供参考）」无效行

- **现场**：线上 `https://dictionary.mangofolio.com/robots.txt` 最后一行。所有爬虫（含 GPTBot/ClaudeBot/Bingbot）读 robots 时都会看到这行水印。
- **危害**：① 暴露内容生成方式，GEO 语境下等于亲手给 AI 引擎贴「机器生成」标签，稀释引用权重；② 属 robots 协议外的无效行，不专业。
- **状态**：✅ 已修复（本轮已删除并随报告提交）。
- **防复发**：`strip-aigc-metadata.py` 目前只扫 `*.md`，建议把 `web/robots.txt`、`web/manifest.json` 等纯文本配置也纳入扫描范围（cron 会往任何它写的文件尾部追加这行）。

### P0-2 五个主页面完全没有 JSON-LD（0 个结构化数据）

- **现场**：index / dictionary / guide / privacy / terms-of-service 五个页面 `application/ld+json` 计数全为 0。词条页反而有 DefinedTerm——头重脚轻。
- **危害**：① 首页缺 `WebSite` + `SearchAction`，Google 不给搜索框 sitelink 增强；② 缺 `Organization`/`WebSite` entity，AI 引擎（Perplexity/豆包/元宝）无法把站点锚定为「投资词典」这个知识实体——GEO 里 entity disambiguation 的地基；③ dictionary.html 缺 `DefinedTermSet`/`CollectionPage`，1038 个词条作为一个「词典集合」的整体性没有被机器表达出来。
- **修复建议**（半小时工作量）：
  ```json
  // index.html 加两块：
  {"@context":"https://schema.org","@type":"WebSite",
   "name":"投资词典","alternateName":"Invest Dictionary",
   "url":"https://dictionary.mangofolio.com/",
   "potentialAction":{"@type":"SearchAction",
     "target":{"@type":"EntryPoint","urlTemplate":"https://dictionary.mangofolio.com/dictionary?q={search_term_string}"},
     "query-input":"required name=search_term_string"}}
  {"@context":"https://schema.org","@type":"Organization",
   "name":"MangoFolio 投资词典","url":"...","logo":".../og-cover.png"}
  ```
  注意：SearchAction 的 target 目前没有 `/search` 页（站内搜索是首页输入框内联结果），要么先用 `dictionary?q=` 建搜索落地页，要么先不加 SearchAction 只加 WebSite。

### P0-3 全站零「新鲜度信号」：sitemap 无 lastmod，词条页无日期

- **现场**：sitemap.xml 1044 条 URL，`lastmod` 计数 = 0；词条页 JSON-LD 与页面正文均无 datePublished/dateModified。
- **危害**：这是「每天 5 条热词」站点的核心卖点，却完全没让机器看到「这站天天在更新」。Google 明确用 lastmod 做重爬调度；GEO 里 freshness 是 AI 引擎决定「引用还是略过」的前三位因素之一（金融词汇的定义会过时）。changefreq=monthly 也没能表达每天新增的事实。
- **修复建议**：generate-sitemap.py 有 dictionary.json 的 id/时间信息来源即可：新词条用生成日期，存量词条用最近一次内容修订日期（git log 可回填）；同批在词条页 JSON-LD 加 `dateModified` + 页面可见的「最后校订：YYYY-MM-DD」一行（可见日期同时服务用户信任）。

### P0-4 E-E-A-T / YMYL 信任链全缺

- **现场**：全站无「关于本站」页、无作者/维护者信息、无联系方式、footer 只有隐私/协议两个入口；无 `Organization` JSON-LD、无 `sameAs`。
- **危害**：投资理财是 Google 质量评估（YMYL）最高审查等级。没有可见的「谁在维护、凭什么信你、怎么找到你」，页面质量评估员指南（QRG）视角下 trust 得分直接封顶不了；AI 引擎做「是否引用」决策时同样会回避无来源实体的内容。
- **修复建议**：新增一页 `about.html`（站名/定位/内容方法学「四卡说人话结构」/免责声明/联系方式），footer 挂入口，sitemap 收录，并配 Organization JSON-LD（name + url + logo + sameAs 指向微博/知乎等社媒账号——正好接上社媒内容线）。

### P0-5 6 个词条页 meta description 为空

- **现场**：`上车 _ 下车`、`信用卡分期手续费（实际IRR）`、`刚性兑付（及其被打破）`、`拉高出货`、`接盘侠（高位接盘）`、`止损（止损线）` 6 页 `content=""`。
- **危害**：SERP 摘要退化为随机抓取正文；分享卡（微信/QQ）无描述；AI 引擎抓取时的"页面自述"缺失。
- **修复建议**：用各自第一卡的一句话人话导语回填（每条 40–80 字，与其他 1032 页同口径）；顺带把「description 非空且 ≥20 字」加进 site-audit.py 的 seo 维度，防 cron 再产出空页。

### P0-6 robots.txt 的 AI 爬虫清单不全

- **现场**：只列了 GPTBot / ClaudeBot / Bingbot / Googlebot / Baiduspider。
- **说明**：缺 OAI-SearchBot（ChatGPT 搜索引用）、ChatGPT-User、PerplexityBot / Perplexity-User（AI 搜索）、**Bytespider（字节系：豆包/今日头条，中文 GEO 必争）**、Google-Extended（Gemini）、Applebot-Extended（Apple Intelligence）、CCBot、meta-externalagent、Amazonbot。目前靠 `User-agent: *` 默认全放行，功能上没问题，但显式声明的好处是：① 未来想对训练类爬虫与引用类爬虫区别对待时有抓手；② 站长日志里能直接统计哪些 AI 引擎来过、来得多勤，为 GEO 效果提供数据。
- **修复建议**：按「引用优先全放行、训练按需控制」原则补全清单。

## 三、🟡 中优先级问题（P1）

### P1-1 43 条词条在首页/词库页无静态锚点（覆盖率 96%）

- **现场**：995/1038 有静态 `<a href>` 内链，43 条（含「M0/M1/M2」「蓝筹股/白马股」等带斜杠简写的高价值词）只在 JS 渲染后出现。
- **危害**：对不执行 JS 的爬虫（部分 AI 爬虫不渲染 JS），这 43 条在首页是孤岛，只靠 sitemap 兜底发现；首页静态内链图也是重要的权重分配通道。
- **修复建议**：sync_all_entries.py 生成静态锚点列表时改为全量（1038 条都渲染成静态 `<a>`——反正现在的实现已经是静态列表，只差补漏）；或在词库页用「本篇章全部词条」静态化兜底到 100%。

### P1-2 无自定义 404 页

- **现场**：`web/404.html` 不存在，Vercel 默认 404（无返回路径、无搜索）。
- **修复建议**：加 404.html：搜索框（复用首页搜索）+ 10 个热门词条 + 面包屑回首页。Vercel 静态站自动使用根目录 404.html。外链打错、旧链接失效的流量能被接住。

### P1-3 www 子域无 DNS 解析

- **现场**：`https://www.dictionary.mangofolio.com/` curl 返回 code=000（域名不存在）。
- **危害**：低。但只要有一处外链用了 www 写法，用户直接 DNS 报错（连重定向机会都没有）。
- **修复建议**：Vercel 项目里 add domain `www.dictionary.mangofolio.com` → 301 到 apex（vercel.json 可配 redirects）。

### P1-4 部署目录卫生：7 类工作文件随站部署

- **现场**（.vercelignore 未覆盖、线上可访问）：
  - `skill_tmp/`、`terms_md_test/`（临时/测试目录）
  - `_existing_slugs.txt`、`_titles_dump.txt`、`titles_dump.txt`（调试产物）
  - `terms_md/`（1038 个 md 源文件）、`markdown/`、`fintools_md/`、`data/`（数据源，可能有用途——见下）
- **危害**：被爬虫抓到会稀释 crawl budget；`titles_dump` 暴露内部文件名清单；同内容 HTML+MD 双份在线，MD 无 canonical（好在 Google 一般只收 HTML 版，风险低但没必要）。
- **修复建议**：`.vercelignore` 追加 `skill_tmp/`、`terms_md_test/`、`*_dump*.txt`、`_existing_slugs.txt`。`terms_md/` 与 `markdown/` 若有「md 源文件公开可读」的产品意图（供 AI 直接抓 md）可保留——**但 robots.txt 需声明哪个是 canonical 内容源**，否则是双份内容。这个建议你拍板：保留（md 对 AI 爬虫友好，算 GEO 加分）或屏蔽（纯减重）。

### P1-5 cron 新页仍按旧模板生成，P0-1 类 .html 后缀 bug 每天复发

- **现场**：今天 cron 生成的「千问（Qwen）」页 canonical/og/相关链接又带 `.html`（本轮已手工修 9 处，门禁才回到 24/24）。昨天修好的 11 页 + 今天 1 页，说明**生成模板本身没修**，只靠门禁事后抓。
- **修复建议**：定位 cron 生成进程的模板（大概率在 `skill/invest-dictionary-generator/templates/` 或某自动化任务里），把 URL 模板里的 `.html` 摘掉；或者让 cron 改用 `scripts/add-term.py`（本轮新加的，URL 形态是对的）。

## 五、其他观察（不计分）

1. **og-cover.png 53KB** —— 体积合格；建议顺手检查微信/QQ 分享卡的实际渲染（JSON-LD 无需改，og:image 是绝对 URL ✓）。
2. **index 401KB / dictionary 549KB** —— 已知技术债，靠 site-audit 的「目录页 600KB 豁免」合规。真要瘦身需改数据加载方式（分片 JSON + 按需注入），属于工程项不属于 SEO 项：对 SEO 无害（静态锚点在 DOM 里），对 LCP 有影响。
3. **sw.js PRECACHE 只有 5 项** —— 轻量正确；注意 precache 里同时有 `/` 和 `/index.html`，cleanUrls 下是同一资源双缓存，无害但可去重。
4. **sitemap 有 `changefreq=monthly`** —— 在没有 lastmod 的前提下聊胜于无；加 lastmod 后可保留。
5. **搜索无独立落地页** —— `search?q=` 链接在词条簇 fallback 里出现，但 `/search` 页不存在（点过去是 404）。本轮 UI 改版后该链接已不存在于未命中路径，但历史版本可能被收录过；建议在 vercel.json 加 `/search` → `/` 的 308。
