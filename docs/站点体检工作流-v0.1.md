# 站点体检工作流 v0.1（检验 → 落地）

> 把「人工看一遍网站」变成「一条命令跑完 + 一份报告 + 一次回归」。
> 适用范围：mangofolio 全部子站（dictionary / fintools / brain / view / forge / investbuddy / 个人主页）

---

## 0. 一句话定位

**体检是手段，落地才是目的。** 本报告体系只保留能直接转成改动作的检查项，不产出"看着不错"的虚分。

---

## 1. 工作流四步

```
① 体检     python scripts/site-audit.py --root <站点目录>
② 定位     读报告 → 按 P0/P1/P2 排序 → 确认修复方案
③ 修复     改令牌 / 改结构 / 改脚本（每次只改一类）
④ 回归     重跑体检 + 跑项目原有门禁 → 对比前后差异
```

**硬规则：每一步都要留下可比对的数字**。没有数字的"优化"不算完成。

---

## 2. 第①步：体检（自动）

```bash
# 基本体检
python scripts/site-audit.py

# 指定子站
python scripts/site-audit.py --root ../fintools/web

# 输出 JSON，接 CI / 存档
python scripts/site-audit.py --json > audit-2026-10-29.json

# CI 收紧模式：WARN 也算失败
python scripts/site-audit.py --strict
```

退出码：`0` = 无 FAIL；`1` = 有 FAIL（`--strict` 下 WARN 计入）。

### 检查项与判定标准

| 维度 | 检查项 | FAIL 阈值 | 为什么 |
|---|---|---|---|
| perf | HTML 体积 | > 100KB | 多半是内联数据 |
| perf | 数据双重下载 | 内联 + 又 fetch 同一份 | 白付双倍流量 |
| perf | 同步 XHR | 出现即 FAIL | `async=false` 冻结主线程 |
| perf | 外链字体 | 引用 fonts.googleapis.com | 国内不可达，934 页全受影响 |
| brand | 一票否决色 | 出现 #C43A31 | 品牌规范 §2.3 |
| brand | CSS 硬编码色值 | 非令牌声明出现 hex | 品牌规范 §2.3 |
| a11y | 对比度 | 文字/底色 < 4.5:1 | WCAG AA |
| a11y | 主按钮 | 文字/底色 < 4.5:1 | WCAG AA |
| seo | 骨架 | 缺 canonical / OG / viewport / lang | 基础 |
| hygiene | 备份文件 | 存在 `.bak*` | 可被抓取成重复内容 |

> 令牌定义行（`--mf-colors-xxx: #hex;`）不算硬编码 —— 令牌是唯一权威源，本来就该写死色值。

### 覆盖不到的部分（必须人工/外部工具补位）

自动脚本只查**可判定的硬伤**。以下必须靠外部工具：

| 缺口 | 补位工具 | 频率 |
|---|---|---|
| 真实性能（LCP/CLS/INP） | Lighthouse / PageSpeed Insights | 每次上线前 |
| 视觉层次、排版、CTA 有效性 | SiteCritic / Pixelait | 改版前 |
| 真实用户行为 | Microsoft Clarity（免费，国内可用） | 常开，观察 ≥1 周 |
| 中文字体体积 | font-spider / cn-fontsub 子集化 | 字体改版时 |

## 3. 第②步：定位（人工判断）

脚本给的是**症状**，不是**处方**。定位阶段要明确三件事：

1. **这真是问题吗？** —— 比如橙色 2.80:1 是真不达标；但"描述字数不一致"不一定是问题。
2. **根因在哪一层？** —— 是令牌层、组件层还是数据层？改错层会反复复发。
3. **改了会影响什么？** —— **改任何数据/脚本前，先查它被谁依赖。**

### ⚠️ 数据类改动的强制前置检查

改数据加载、同步、生成链路前，**必须**先查清楚依赖方：

```bash
grep -rn "关键词" --include="*.py" --include="*.js" --include="*.ps1" .
```

invest-dictionary 的实际案例（2026-10-29）：

- 想删首页内联 `ALL_ENTRIES`（378KB）→ 先查依赖，发现三处：
  - `scripts/sync_all_entries.py` —— 找不到该数组会 `sys.exit(1)`
  - `scripts/check-consistency.py` 第 6 项 —— 找不到会直接 FAIL，**阻断提交**
  - `scripts/batch_fill_1000.py` —— 每批结束自动调同步
- 结论：**不能只删数据**，必须连同脚本与门禁一起改，否则日常热词入库流程会断。

> 教训写进 `docs/PITFALLS.md`。这类"看起来是清理、实际是改链路"的操作最容易翻车。

## 4. 第③步：修复（一次一类）

按优先级，每批只改一类，便于回归定位：

| 批次 | 内容 | 风险 |
|---|---|---|
| P0 | 阻塞主线程、阻断渲染的东西（同步 XHR、大内联数据） | 需先查依赖 |
| P0 | 对比度不达标 | 低（改令牌，全站生效） |
| P1 | 品牌违背（硬编码色值、否决色、随站备份文件） | 低 |
| P1 | 布局对齐（网格等高、CTA 对齐、描述限行） | 中（需实拍验证） |
| P2 | 移动端触控区、折行、间距 | 中 |

### 品牌色的正确改法：先换文字色，别动色相

> 这一节是踩过坑后重写的。原方案写的是「把 `#F97316` 压暗成 `#C2410C`」，
> 对比度确实达标（5.18:1），但**色相从 24.6° 被拽到 17.5°，橙变成了铁锈红**——
> 数字达标，品牌没了。这是自动化检查最容易漏掉的一类错误：**只验对比度、不验色相**。

对比度不足时，按优先级选：

| 优先级 | 做法 | 示例 | 效果 |
|---|---|---|---|
| 1 | **换文字色**，底色不动 | 橙底 `#F97316` + 深墨字 `#2A2420` | 5.46:1 ✅ 品牌色一分不改 |
| 2 | **只降明度、锁死色相** | `#F97316` → `#B45309`（24.6° → 26.0°） | 5.02:1 ✅ 仍是橙 |
| 3 | ❌ 压暗同时移色相 | `#F97316` → `#C2410C`（17.5°） | 达标但变铁锈红，**不可用** |

```css
--mf-colors-accent-decor: #F97316;        /* 纯装饰：渐变、插画、角标 */
--mf-colors-background-primary: #F97316;  /* 品牌橙不动，配深墨字 */
--mf-colors-text-on-primary: #2A2420;     /* 橙底上的字：5.46:1 */
--mf-colors-text-link: #B45309;           /* 文字档：色相 26°，5.02:1 */
--mf-colors-border-on-primary: rgba(36,22,16,.32); /* 补 WCAG 1.4.11 边界 3:1 */
```

**注意**：深色按钮的 hover 要**提亮**（`#FB8B3D`）而不是压暗——压暗会让深墨字对比度跌破 4.5:1。

已固化为体检第 20 项「主色色相漂移」：以 `#F97316` 为锚点，下探只允许 5°（防变红），上探允许 12°（防变金）。改完跑一次就知道有没有跑偏。

## 5. 第④步：回归（自动 + 实拍）

```bash
# 1. 重跑体检，对比数字
python scripts/site-audit.py

# 2. 跑项目原有门禁（确认没引入新 FAIL）
python scripts/check-consistency.py

# 3. 实拍对比（自动脚本查不出视觉问题）
python -m http.server 8899 --directory web
msedge --headless=new --screenshot=after.png --window-size=1440,2600 http://127.0.0.1:8899/
# 移动端必拍：--window-size=390,2600
```

**判定标准：体检 FAIL 数下降，且门禁 FAIL 数不增加。**

> 门禁若本来就 FAIL（如计数漂移），要区分「我引入的」和「本来就有」——
> 方法：改动前先跑一次留底，改完再跑，只对我引入的负责。

## 6. 落地到 mangofolio 其他子站

各子站差异主要在品牌令牌，用 `--config` 覆盖即可：

```json
// audit-config-fintools.json
{
  "forbidden_colors": ["#C43A31"],
  "max_html_kb": 100,
  "cn_unreachable_hosts": ["fonts.googleapis.com", "fonts.gstatic.com"]
}
```

```bash
python scripts/site-audit.py --root ../fintools/web --config audit-config-fintools.json
```

### 建议纳入 CI

```yaml
# .github/workflows/site-audit.yml
- run: python scripts/site-audit.py --strict
```

## 7. 与现有脚本的分工

| 脚本 | 职责 | 何时跑 |
|---|---|---|
| `check-consistency.py` | **数据一致性**门禁（计数/唯一性/断链/sitemap/ALL_ENTRIES） | 提交前必跑 |
| `sync_all_entries.py` | 把 dictionary.json 同步进首页内嵌数组 | 新增词条后 |
| `generate-sitemap.py` | 从 dictionary.json 重建 sitemap | 新增词条后 |
| **`site-audit.py`（本工作流）** | **质量体检**（性能/品牌/无障碍/SEO/卫生） | 改版前后、定期 |

两者不重叠：一个管数据对不对，一个管页面好不好。
