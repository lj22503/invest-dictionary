# 信源抓取管线设计（场景数据自动化）

> 目标：把「信源 → 8 场景数据」做成每日自动化管线，机制对齐每日热词（daily_hot KV + 静态兜底）。
> 范围：只做数据管线自动化，不含前端展示改造。
> 状态：v0.1 设计稿，2026-10-30 当日手工抓取已验证信源可用。

- 只抓当日（北京时间）内容，禁止把隔夜海外行情误当当日

- 数值类事实必须有出处，禁止凭记忆补数
- 抓取失败不硬编，缺失场景如实留空

## 2. 自动化管线设计（怎么跑）

```
[定时任务·每日 08:30]
      │
      ▼
[1. 按信源清单抓取当日热点]   ← 主 Agent 按 1.1 清单逐源抓取（web_fetch/web_search）
      │
      ▼
[2. 提炼 5~10 条核心事实]     ← 保留时间/数值/来源URL，去重、防旧闻
      │
      ▼
[3. 按 8 场景生成用户提问示例] ← 每场景对应一个 Skill 输出结构（见 §3）
      │
      ▼
[4. 按场景落盘 web/data/hot-scenario-{scene}.json]  ← 每场景独立文件、按需独立更新，结构与 daily_hot 同模式
      │
      ▼
[5. 写 KV hot_scenarios]      ← 后续接 POST /api/hot-scenarios（对齐 hotwords.js）
      │
      ▼
[6. 概念词条联动]              ← 新概念按需同步 dictionary.json 更新链路
```

### 2.1 与每日热词机制逐项对齐

| 维度 | 每日热词 | 场景数据 | 对齐 |
|---|---|---|---|
| 触发 | 每日定时任务 | 每日定时任务 08:30 | 同模式 |
| 信源 | 主 Agent web_search 选词 | 主 Agent 按清单抓取 | 同方式 |
| 落盘 | seed.md → 词条页 + hotwords.json | 每场景独立文件 hot-scenario-{scene}.json，可按需只更新指定场景 | 独立更新 |
| 存储 | KV `daily_hot` | KV `hot_scenarios`（待建接口） | 同模式 |
| 静态兜底 | dictionary.json 前5条 | web/data/hot-scenario-{scene}.json（8 场景各一文件） | 同模式 |

## 3. 8 场景 × Skill 输出结构映射（数据字段规范）

每个场景的数据项：`scene / title / question / answer / hot / sources[] / tags[]`。
其中 `answer` 必须按对应 Skill 的**输出结构**生成，不允许自创问答格式：

| 场景 | 对应 Skill | answer 必须遵循的结构 |
|---|---|---|
| 01 查词学词 | mangofolio-symptom-lookup（理财急诊） | 症状 → 对应词条 → 人话解释 |
| 02 看新闻 | mangofolio-combo-narrative（新闻翻译机） | 一句话/概念人话/因果链≤4步/对你意味着什么/今天可做 |
| 03 持仓亏了 | mangofolio-symptom-lookup（理财急诊） | 现象 → 词条倒查 → 能做什么/不能做什么 |
| 04 产品对比 | mangofolio-duel-compare（二选一擂台） | 场景校验/同场景四维对比/分界线/试算 |
| 05 重大决定 | mangofolio-decision-mosaic（决策拆解桌） | 拆变量 → 判断条件 → 决策提示 |
| 06 防坑提问 | mangofolio-question-probe（防坑提问器） | 该问什么 → 问题清单 → 识别话术 |
| 07 复杂事件 | concept-combinator（概念串联） | 概念识别 → 因果链 → 落到行动点 |
| 08 今日热词 | mangofolio-daily-hotword（每日热词） | 词条 + 一句话人话 + 关联词 |

**合规红线**：所有 answer 保留"不构成投资建议"；例子永远是"用户提问示例"，禁止买卖建议语气。
