# 每日归档页（/daily/）设计

> 目标：把每天管线产出的 8 场景数据变成**可被收录的站内文章**，同时不让站点变成 365 个同类页面的堆场。
> 决策时间：2026-11-10 · 状态：待实施（本文只定规则，未写页面）

---

## 1. 先回答三个范围问题

| 问题 | 决定 | 理由 |
|---|---|---|
| 首页要不要露 8 场景 | **只露一个入口**，不露内容列表 | 首页已有「今日热词」+「7 个场景」两块，再加一块会挤；用户要的是「知道今天有」，不是「读完今天」 |
| 历史页面怎么藏 | 不藏，**沉在 /daily/ 归档**，按月份分组 | 藏起来 = 放弃收录；沉下去 = 有内链、可检索，但不占首页 |
| 怎么导回本站 | 每期页内「这条链上的词条」→ `/terms/xxx` | 这是唯一有长期复利的方向：文章赚流量，词条接流量 |

---

## 2. 目录与 URL

```
web/daily/index.html        →  /daily            归档列表（按月分组，倒序）
web/daily/2026-11-10.html   →  /daily/2026-11-10 单期详情
```

`cleanUrls: true` 自动处理，不写 `.html`。

**不做**：分页（前期量小）、标签页 `/daily/tag/xxx`（不足 30 篇时全是薄页）、日历视图。

---

## 3. 首页只放一个入口

在 `#daily-hot` 模块底部加一行（**构建期写入**，不是 JS 渲染）：

```html
<p class="daily-entry">
  今天还有 5 个问题：CPI 与 PPI 谁在拖谁、24% 关税续到什么时候、煤炭这波该问哪几句
  <a href="/daily/2026-11-10">看今天这一期 →</a>
</p>
```

- 构建期注入 → 爬虫能读到，且「今天」永远是部署当天，不需要客户端判断过期
- 首页体积增量约 300 字节，可忽略
- 只链**最新一期**，历史期不出现在首页任何位置

---

## 4. 内容分流：8 条里只有 5 条该进归档

这是本设计的核心判断。**质量不取决于字数，取决于内容的差异度**——同一天写 8 条不难，连续 30 天每条都不一样才难。

| 类型 | 场景 | 去处 | 判定依据 |
|---|---|---|---|
| **事件型** | s02 看新闻、s03 持仓亏了、s05 重大决定、s06 防坑提问、s07 复杂事件 | ✅ `/daily/日期` | 每天的事实不同，标题能具体到现象（「1.49 万亿缩量里跌的是锂矿和光伏」） |
| **概念型** | s01 查词学词、s08 今日热词 | ⛔ 进归档 → 转常青页 | 每天都是「CPI 是什么」，做成每日页 = 每页 80% 重复，典型薄内容 |
| **产品型** | s04 产品对比 | ⛔ 进归档 → 转 `/compare/A-vs-B` | 同上；且「产品对比」页碰投资建议红线，只做**概念对比**（红利 vs 成长、票息 vs 价差） |

实施上不删数据：`hot-scenarios.json` 仍保留 8 条（供专家上下文、邮件、首页热词用），只是**归档时按 scene 白名单过滤 5 条**。

## 5. 三层质量把关

### L1 机械检查（不过就不落地）

脚本 `scripts/check-daily.py`，逐条检查：

| # | 检查 | 阈值 | 不通过后果 |
|---|---|---|---|
| 1 | 事件型 5 条齐全，id 唯一不重复 | 必须 | 阻断 |
| 2 | `answer` 长度 | 400–1500 字 | 阻断（<400 是糊弄，>1500 手机读不完） |
| 3 | 末尾含「不构成投资建议」 | 必须 | 阻断 |
| 4 | `sources` 条数 + 可点性 | ≥2 条，全部 `[文本](https://…)` | 阻断 |
| 5 | 来源域名白名单 | 同花顺/东财/网易/腾讯/新浪/新华财经/财信 | 阻断（防野鸡源） |
| 6 | **`answer` 点名的词条必须真实存在** | 0 缺失 | 阻断（复用 `check-skill-terms.py` 匹配逻辑） |
| 7 | `hot` 字段含数字 + 日期 | ≥2 个数字、1 个日期 | 阻断（防"没有事实的空议"） |
| 8 | 禁词扫描 | 见下 | 阻断 |
| 9 | 与前一日的标题相似度 | < 0.8 | 阻断（防"换个数字的同一篇"） |

**禁词表**（命中即拒）：
- 荐股类：`建议买入` `建议卖出` `可以加仓` `减仓` `目标价` `满仓` `抄底`
- 收益承诺：`稳赚` `保本` `必赚` `年化\d+%` `翻倍`
- 预测类：`必涨` `必将` `一定会上涨` `会涨到`
- 伪权威：`内幕` `据说` `可靠消息`

第 6 条是整套把关里最硬的一条：**它把"AI 说的话"变成了"可机械核对的话"**。answer 里出现的每个概念名，要么在 1125 条词条里真实存在，要么就是编的。

### L2 人工闸门（发布开关）

```
web/data/daily/pending/2026-11-10.json   ← 管线写入，不对外
web/data/daily/published.json            ← 白名单，人工确认后追加
```

```bash
python scripts/check-daily.py 2026-11-10              # L1 检查
python scripts/build-daily.py --publish 2026-11-10    # 通过才生成 HTML + 进 sitemap
```

未发布的日期：不生成 HTML、不进 sitemap、不出现在 `/daily/` 列表。
**理由**：自动生成的内容直接上线，错一次（数字抄错、来源失效）的代价远大于每天多点一次确认。

### L3 上线后

`site-audit.py` 新增 3 项：
- `web/daily/*.html` 数量 == `published.json` 条目数 + 1（列表页）
- 每页 canonical + Article JSON-LD + `datePublished` 齐全
- 每页至少 1 个 `/terms/` 内链（「导回本站」的硬指标，没有就是白赚流量）

## 6. 单期页结构

```
/daily/2026-11-10
  H1   2026 年 11 月 10 日 · 今天该问的 5 个问题
  导语  今天事实里最反常识的一条（1 句）
  ── 5 个 section（每个含）
       H2     标题要点（具体到现象，不是"市场综述"）
       引用块  用户会这样问（question 原文）
       正文    answer 全文（已含 4-6 个小标题）
       来源    sources（可点外链，rel="nofollow noopener"）
       词条    从 answer 抽出的词条 → /terms/xxx（本站内链）
  ── 底部
       前一天 ←   → 后一天        时间序列内链
       相关词条 5-8 个             跨期聚合
```

**`sources` 外链加 `rel="nofollow noopener"`**：外链是引用证据，不该把权重送出去；内链（词条）才是要养的。

## 7. 上线节奏

| 阶段 | 动作 | 观察指标 |
|---|---|---|
| 第 1 周 | 只发 7 期（11-04 ~ 11-10），不发新页 | Search Console 收录数、`/daily/` 列表页是否有抓取 |
| 第 2 周 | 收录 ≥5 期 → 继续；<3 期 → 停下查原因（多半是内容同质 or 站点权重不够） | 每期平均被收录耗时 |
| 稳定后 | 每日 1 期，`/daily/` 列表页按月折叠 | 从 `/daily/` 到 `/terms/` 的点击率 |

**先发 7 期不是为了省事，是为了留退路**：如果搜索引擎不认，止损成本是 7 个页面；如果一上来发 30 期，出问题要批量下线。
