# 词条接口设计

> 解决一件事：技能不该让模型当模板引擎。
> 状态：`/api/term-search`、`/api/term-page` 已实现并本地跑通，尚未部署。

## 1. 为什么改

改之前，「投资翻译」技能生成一个 HTML 词条页要模型做这些事：

| 环节 | 体量 |
| :--- | :--- |
| 读 `SKILL.md` | 11.8 KB / 约 3.5k token |
| 读 `templates/term-page-baseline.html` | 32.4 KB / 约 8k token |
| 写出整页 HTML | 31 KB / 约 8k token |

输出那 8k token 是一个字符一个字符吐出来的，40–60 tok/s 下就是两三分钟。
界面越精致，模型越慢——这是结构问题，不是提示词写得不好。

同时模板随包下发到用户磁盘，等于把版式资产一起送出去。

## 2. 两个接口

都在 `web/api/`，Vercel Edge 运行时，与现有 `hot-search.js` 同一套。

### GET /api/term-search

```
GET /api/term-search?q=CPI&n=5
→ { ok, q, n, total, hits: [{ t, u, c, k, s }] }
```

| 字段 | 含义 |
| :--- | :--- |
| `t` | 词条名 |
| `u` | 站内链接 |
| `c` | 所属章节 |
| `k` | 四张卡片的小标题（等于内容提纲） |
| `s` | 匹配分，仅调试用 |

排序：完全相等 100 ＞ 前缀 80 ＞ 包含 60 ＞ 被包含 50 ＞ 卡片标题命中 25 ＞ 章节命中 10。
返回约 1 KB，替代原来 51 KB 的 `term-index.txt`。

### POST /api/term-page

传结构化 JSON，返回整页 HTML（`content-type: text/html`）。

```json
{
  "title": "货币",
  "summary": "一句话定义，≤160 字，进 meta 描述",
  "chapter": "第一篇：钱的本质",
  "keywords": ["信用", "购买力"],
  "cards": [
    {
      "q": "你手里攥着的**100块**",
      "body": [
        { "p": "段落" },
        { "quote": "金句" },
        { "ul": ["步骤一", "步骤二"] },
        { "note": "浅色小字" }
      ]
    }
  ],
  "related": ["信用", "购买力"]
}
```

- `summary` / `cards` 必填，`cards` 2–6 张，每张必须有 `q` 且 `body` 非空
- `chapter` 缺省时按词条名反查章节；`related` 缺省取同章节词条
- 正文 `**词**` → 马克笔高亮，`__词__` → 米色胶囊标签；其余字符全部转义
- 响应头：`x-term-url`（正式地址）、`x-term-bytes`
- `?format=json` → `{ ok, url, bytes, html }`，便于程序处理
- 校验不过 → 400 + `errors` 数组，模型照着改 JSON 重传

服务端补齐的部分：`<title>`、meta description/keywords、canonical、OG、Twitter Card、
Schema.org `DefinedTerm`、面包屑、相关词条、上下篇、页脚、免责声明。
**这些都不再允许模型自己写**，写就是错。

## 3. 实现方式：抽壳

`web/terms/货币.html` 是已上线的词条页，样式与页脚都在里面。构建脚本把它的动态部分
换成占位符，得到整页外壳：

```
web/terms/货币.html
   ↓ scripts/build-term-api.py（把 title/description/正文/面包屑… 换成 @@TOKEN@@）
web/api/_term-shell.js     SHELL：整页 HTML 字符串 + 占位符（25 KB）
web/api/_term-index.js     INDEX：1130 条紧凑索引（303 KB）
web/api/_term-render.js    渲染逻辑：JSON → 各段 HTML → 替换占位符
```

抽壳用 `re.subn(..., count=1)` 并对命中数做断言：样式改动导致某个正则失配时，
构建会直接失败，而不是静默产出一个没有动态内容的页面。

**改了站内词条页样式，必须重跑 `python scripts/build-term-api.py`。**
门禁「词条页接口资源与站内页面一致」会跑 `--check` 比对，忘跑会 FAIL。

## 4. 本地验证

```bash
node --experimental-default-type=module scripts/test-term-api.mjs
```

会对 5 个关键词走一遍查词、渲染一页到 `dist/term-api-out.html`、并检查
残留占位符、canonical、JSON-LD、上下篇、空入参报错。

视觉核对：把产物复制成 `web/terms/_apitest.html`，与 `web/terms/货币.html` 同视口比对，
比对完删掉。

## 5. 还没做的

1. **其余 7 个技能仍用本地 `grep`** 查词。它们不是慢的主因（一次只花约 100 token），
   但接口能多给「章节 + 卡片小标题」，判断质量更好，可以陆续切。
2. **`/api/daily-brief`** 没做：当日 8 场景数据已经落 `hot-scenarios.json`，
   但消费方（页面）已被撤掉，等有消费场景再做。
3. **MCP 不做**：MCP 只压缩输入，不解决输出；真正慢的是让模型写 HTML，
   接口已经解决。等接口稳定、需要「连接器」这个分发位时再包一层。
