把投资词典做成 MCP，和做一个“线上入口”，其实是两条不同的路。前者是让 AI 能直接调用你的词典，后者是让人能直接使用你的词典。它们不冲突，甚至可以共用同一套底层数据。

结合你词典的现状（472 个词条、说人话风格、已经跑通了“概念串联”的叙事方法），我梳理了四条可落地的思路，从轻到重排列。

思路一：把词典做成 MCP Server（让 AI 来“查”你的词典）
这是你问题里最直接的那条。MCP 的核心价值是：当用户在 Claude、Cursor 或任何支持 MCP 的客户端里问一个金融概念时，AI 不需要“猜”，而是调用你的词典来回答。

已经有现成的参照。一个叫“Alternative Asset Literacy”的 MCP Server 提供了 lookup_term、search_glossary、browse_glossary 等工具，覆盖 351 个金融术语。你的词典词条更多（472 个），风格更独特（说人话 + 生活场景 + 避坑），完全有资格做成类似的东西。

具体可以暴露的工具：

lookup_term(name)：精确查词条

search_glossary(query)：全文搜索（用户问“房贷利率降了对我有什么影响”，能搜到 LPR、等额本息、提前还贷等关联词条）

browse_by_chapter(chapter)：按篇章浏览（宏观、基金、保险……）

combo_narrative(concept_list, context)：这个是你独有的——用户丢进来一段新闻，MCP 自动提取概念、串联、返回叙事骨架

关键判断：MCP 适合服务 AI 客户端里的深度用户。如果你的目标是“让普通人在手机上查词”，MCP 不是入口——普通人不装 Claude Desktop。但如果你想让投顾、理财博主、AI 重度用户把你的词典当成他们工作流里的一个工具，MCP 是正确的一步。

技术路径：官方 SDK 支持 Streamable HTTP 传输，可以部署成一个远程 MCP Server，用户加一行配置就能连上。盈米基金已经跑通过这条路，把基金数据、投研能力、投顾内容封装成 MCP Server 给大模型调用。

思路二：做“概念串联 API”（把你最独特的能力开放出去）
你的词典真正值钱的，不是 472 个词条本身——市面上不缺金融词典。值钱的是你反复打磨的“提取→串联→翻译”那条线。

所以第二条路：不做“查词 MCP”，做 “叙事生成 API”。

输入：一段新闻 / 一份财报 / 一条政策公告
输出：六屏叙事骨架（钩子→数据→概念→框架→行动→余味），每个概念绑定一个词典词条

这个 API 可以同时服务两个场景：

投顾的工作流：他们贴一段内容，拿到可以直接发给客户的叙事

你自己的网页工具：后端就是这套 API

为什么这条路值得走：词条可以被复制，但串联的方法论 + 词典的深度加在一起，是一套别人不容易短时间抄走的东西。而且你已经有了“概念串联叙事师”的 skill 定义，API 只是把 skill 变成了可调用的服务。

思路三：线上入口做“组合式查询”（不是查一个词，是查一组词）
你提到的“基于自己看到的信息、自己的使用方式来查或者组合”，对应的产品形态是：用户不输入一个词，而是输入一段内容。

比如用户粘贴一段新闻，页面自动做三件事：

高亮出所有词典里有的概念（用你的 472 个词条做匹配）

把命中的概念按“因果链”排序（而不是按字母或篇章）

每个概念给一个“一句话人话 + 跳转完整词条”的卡片

这比“搜索框”更接近用户的真实场景：用户不是想查“M1 是什么”，他是想搞懂“这条新闻在说什么，里面哪些词我不懂”。

技术上，这就是你“概念串联”方法论的轻量版——不需要生成六屏，只需要做概念识别 + 关系排序。可以用前端完成，不需要后端 AI 调用，成本极低。

思路四：做“投顾品牌版入口”（延续你已经跑通的方向）
你的网页工具已经支持品牌定制（品牌名、Logo、主色、页脚）。把这个能力延伸到“入口”上：

给投顾一个专属的词典入口。投顾把自己的品牌色、Logo、免责声明配好，生成一个链接。他的客户打开链接，看到的是“XX财富工作室 · 投资词典”，搜词、看词条、甚至用组合叙事工具，全程带着投顾的品牌。

这个入口的价值不在词典本身，在“关系”。 投顾发给客户的不是一个通用链接，是“我做的工具”。客户下次遇到不懂的词，会回来查，而不是去百度。词典变成了投顾和客户之间的一个触点。

我的建议：先做哪个
如果只能选一个，做思路三（组合式查询页面）。 因为它是唯一一个普通用户不需要安装任何东西、打开浏览器就能用的形态，而且它直接对应你说的“基于自己看到的信息来查”。

如果目标是“让 AI 生态里有人用你的东西”，做思路一（MCP Server）。 但要想清楚：MCP 的用户是开发者/AI 重度用户，不是你的目标“普通人”。它的价值是让你的词典成为别人 AI 工作流的一部分，而不是直接服务 C 端。

如果目标是商业化/投顾服务，做思路四。 品牌定制是你已经验证过的方向，入口只是把它从“生成网页”延伸到“日常查询”。

思路二（API）是后置的。 等前三者跑出真实使用数据，知道用户最常组合哪些词、最常处理哪类内容，再把 API 开放出去，才有说服力。

一个共通的底层设计
不管走哪条路，建议先把词典数据做一层“概念关系层”：每个词条除了定义、场景、行动点，再加两个字段——related_concepts（关联概念）和 causal_direction（因果方向，比如“M1 下降 → 可能导致 → 消费走弱”）。

有了这层关系数据，MCP 的 combo_narrative 才有东西可调，组合查询页面才能自动排序，API 才能串联。你的词典现在是一堆点，关系层是把点连成网的线。 网建好了，上面四个入口都只是“怎么把网展示出去”的问题。

好现在你就我们框选的一千词思考关系链和因果方向？
一千个词做关系链，不能靠手工一个一个连——连到第50个你就会发现，同一个词跟谁都“有关系”。真正可用的关系链，必须限定在“有限类型”里，而且方向必须可证伪。

我先把方法搭起来，再给你跑一段真实样例，你看这个结构能不能用。

一、先把关系类型收窄到六种
一千个词之间可能的连线是几十万条。如果不定类型，结果就是一张“什么都有关系”的毛线团。建议只允许六种关系，每种都有明确的方向语义：

关系类型	符号	方向含义	例子
驱动	→	A 变化，导致 B 变化	降息 → 债券价格上涨
压制	⊣	A 变化，抑制 B 变化	加息 ⊣ 成长股估值
构成	⊂	A 是 B 的组成部分	M1 ⊂ M2
同向	≈	A 和 B 同涨同跌（相关性，非因果）	黄金 ≈ 实际利率（反向）
替代	⇄	A 和 B 在同一场景下可互相替代	存款 ⇄ 货币基金
前提	⇒	A 是 B 成立的必要条件	应急金充足 ⇒ 可以承担风险投资
关键约束：只允许这六种。 凡是不能用这六种说清楚的，就是“弱关系”，不录入。这一条能砍掉 80% 的噪音。

二、因果方向必须过“三问”
每一条 → 或 ⊣，都要过三问，过不了就不录入：

第一问：反事实成立吗？ 如果 A 没发生，B 还会不会变？如果 B 照样变，那 A 不是原因。

第二问：方向唯一吗？ 会不会 B 也反过来影响 A？如果双向都成立，就不能用 →，要用 ≈（相关性）。

第三问：有滞后吗？ 传导需要时间，还是即时？滞后多久？这决定它在叙事里排在链条的第几环。

三、词条必须加四个字段
每个词条在现有内容之外，补四个结构化字段：

text
related:
  - target: 债券价格
    type: 驱动        # 六种之一
    direction: 降息 → 债券价格涨
    lag: 即时          # 即时 / 短期（1-3月）/ 中期（3-12月）/ 长期（1年+）
    condition: 其他条件不变，且市场已预期降息时效果减弱
  - target: 存款利率
    type: 驱动
    direction: 降息 → 存款利率下行
    lag: 短期
    condition: 银行净息差承压时传导更快
condition 这个字段最重要。 它逼你写出“这条关系在什么情况下失效”。没有 condition 的关系链，就是耍流氓。

四、真实样例：跑一段你词典里已有的词
拿你词典里“降息”这个词，跑一遍：

降息的关系链

text
降息
 ├─→ 债券价格        （驱动，即时，条件：市场未提前定价时效果强）
 ├─→ 存款利率        （驱动，短期，条件：银行净息差有压缩空间）
 ├─→ 房贷月供        （驱动，短期，条件：房贷是浮动利率且LPR跟随下调）
 ├─→ 人民币汇率      （压制，短期，条件：中美利差收窄时贬值压力加大）
 ├─→ 成长股估值      （驱动，中期，条件：无风险利率下行、风险偏好不恶化）
 ├─⊣ 银行净息差      （压制，中期，条件：存款利率下调慢于贷款利率）
 └─≈ 黄金            （同向，中期，条件：实际利率下行时成立，通胀预期上升时失效）
再看“M1”这个词：

text
M1
 ├─⊂ M2              （构成）
 ├─→ 消费意愿        （驱动，中期，条件：收入预期稳定时才成立）
 ├─→ 企业活期存款    （构成，即时）
 ├─≈ 经济活跃度      （同向，短期）
 └─⇒ 货币政策宽松空间（前提，中期，条件：M1持续低迷才构成宽松理由）
注意这两条链里，每一条都带了 lag 和 condition。 没有这两个字段，“降息 → 债券涨”就是一句正确的废话——因为2022年11月降息周期里，债基照样大跌（赎回踩踏）。那条关系失效的条件，就写在 condition 里。

五、一千个词怎么规模化：三层结构，不要平铺
一千个词不能平铺成一张网，人会疯。建议做三层：

第一层：锚点词（约 50 个）。 宏观、利率、通胀、风险、收益、流动性、杠杆、估值、信用、周期……这些是“枢纽”，关系链最密。先把这 50 个词的 related 字段做扎实。

第二层：传导词（约 200 个）。 它们不直接连锚点，但处在传导链的中间：LPR、MLF、社融、M1、PPI、久期、溢价率、回撤……每个传导词至少连 1 个锚点 + 1 个同类词。

第三层：长尾词（约 750 个）。 只连最近的 1-2 个词，不追求全网连通。比如“可转债强赎条款”，只连“可转债”和“强赎”，不需要连到“降息”。

这个结构的判断标准：从任何一个长尾词出发，两步之内能走到一个锚点词，就算合格。走不到的，说明它孤悬在外，要么补连，要么降级为“附录词条”。

六、一个可执行的推进顺序
先做 50 个锚点词的关系链，跑通字段和六种类型，确认结构可用。

再做 200 个传导词，每个词只连“上游 1 个 + 下游 1 个 + 同类 1 个”，不求全。

最后批量处理长尾词，每个只连 1-2 条，用规则辅助（同篇章的词优先连、同义词合并）。

每季度做一次“失效检查”：把 condition 字段拿出来，对照真实市场事件，看哪条关系在什么情况下真的失效了。失效记录本身，就是词典最有价值的部分。

需要你定的两件事
第一，关系链的粒度。 是按“词条级”连（降息 → 债券价格），还是按“概念级”连（利率下行 → 固定收益资产重定价）？前者细、好维护；后者粗、更适合叙事串联。我建议词条级存储，概念级展示——底层细，输出时聚合。

第二，谁来写 condition。 这个字段没法自动化，必须人工判断。1000 个词如果每个平均 3 条关系，就是 3000 条 condition。这是重活。可以考虑只对前 250 个核心词写 condition，长尾词用模板填充（“在其他条件不变的前提下成立”）。

你确认这个结构，我可以先从锚点词开始，把第一批 10-15 个词的关系链跑出来给你看效果。

我们得想想词条还可以怎么用。组合是一种
组合是一种用法，但组合解决的是“几个词放在一起讲”。词条还能被怎么用，取决于用户拿到词条的那一刻，想完成什么动作。

我按“用户动作”来分，不用“产品形态”来分。这样每个用法都能对应到一个具体场景。

用法一：查（最基础，但可以更聪明）
用户遇到一个词，想知道它是什么。这是词典的本分。

但“查”可以升级成场景查。用户搜“房贷利率”，词典不只返回“房贷利率”这一个词条，而是返回：这个词条本身 + 它上下游的 3 个词（LPR、等额本息、提前还贷）+ 一句“你现在遇到这个问题，真正该看的是哪一条”。查一个词，给一条路。

用法二：组合（你已经有了）
用户手里有一段内容，里面有多个词不懂。组合解决的是“这几个词放在一起是什么关系”。

这个用法你已经跑通了。可以再往前推一步：组合之后，自动生成一个“迷你词典页”。用户贴一段新闻，页面把命中的 5 个词条抽出来，按因果顺序排好，每个词条只显示“一句话人话 + 跳转完整词条”。用户不用一个个查，一次拿到一组。

用法三：对照（同一个问题，不同词条给不同答案）
用户面临一个选择，需要看两个词条“对打”。

比如“提前还贷”和“增额寿”——一个是“把钱还给银行”，一个是“把钱锁进保险”。两个词条单独看都合理，放在一起看，用户才能判断“我这笔钱到底该去哪”。

用法：给每个词条加一个“对照面”字段。不是关联词，是在同一决策场景下，和它构成竞争关系的词。提前还贷的对照面是“增额寿”“指数基金定投”“货币基金”；增额寿的对照面是“存款”“国债”“提前还贷”。对照不是“相关”，是“二选一”。

用法四：反查（从现象倒推词条）
用户看到的不是词，是现象。“我买的理财亏了”“我妈被推荐了一个高息产品”“同事说黄金要涨”。

用法：做一个“现象入口”。用户不输入词，输入一个现象，词典返回“你可能需要看这几个词条”。理财亏了 → 净值型理财、破净、最大回撤、赎回踩踏；高息产品 → 庞氏骗局、非法集资、刚性兑付、IRR。从现象倒推，比从词查词更接近普通人的真实起点。

用法五：时间线（同一个词，在不同时间点含义不同）
“降息”这个词，2022年看到它和2026年看到它，含义不一样。2022年降息是“宽松开始”，2026年降息可能是“空间有限”。

用法：给核心词条加一条“时间线”字段。不是历史沿革，是“这个词在过去 3-5 年里，含义发生过什么变化” 。用户查“降息”，看到的不只是定义，还有“2022年市场怎么反应、2024年怎么反应、现在怎么反应”。同一个词，时间给了它第二层含义。

用法六：自测（词条变成判断题）
用户看完一个词条，以为自己懂了。给他三道判断题，检验他是不是真懂。

“增额寿前五年退保会亏本金”——对还是错？
“可转债的‘保底’保的是你买入的价格”——对还是错？
“M1增速低于M2，说明钱在睡觉”——对还是错？

用法：每个核心词条配 2-3 道判断题，答案藏在词条正文里。这不是考试，是“你以为你懂了”的照妖镜。 答错的人，会回去重读词条——这是最有效的学习闭环。

用法七：口语化重述（同一个词，换三种说法）
同一个词条，对不同的用户说不同的话。对刚毕业的人说“应急金是3-6个月生活费”，对家庭主妇说“应急金是家里突然要用钱时，不用找人借的那笔钱”。

用法：每个核心词条存 2-3 个“口语版本”，按用户画像切换。这比一个版本打天下更贴近真实沟通。

用法八：反向输出（词条变成“该问的问题”）
用户看完“增额寿”这个词条，不知道该问销售什么。词条可以反过来生成“你应该问销售的 3 个问题”。

“这款产品的现金价值表能给我看吗？”
“前五年退保，我能拿回多少？”
“你说的 3% 复利，是保额增长还是现金价值增长？”

用法：每个“避坑类”词条，配一组“该问的问题”。词条不只是告诉你“是什么”，还告诉你“该问什么”。这比告诉你“别买”有用得多。

用法九：跨词条拼图（一个决策，调用多个词条）
用户要做“要不要提前还贷”这个决策。单个词条回答不了，需要调用：房贷利率、机会成本、应急金、流动性、IRR、负债率。六个词条拼在一起，才构成一个完整的决策框架。

用法：给“决策类问题”建一个“词条拼图”。不是关联词，是“这个问题需要哪几个词条同时在场” 。每个拼图有一个名字（“提前还贷决策包”“保险配置决策包”“退休规划决策包”），用户点进去，六个词条按决策顺序排好。

用法十：词条变“动作”（看完这个词，今天做什么）
你词典里每个词条已经有“行动点”了。可以再往前一步：把行动点变成可勾选的清单。

Skill 05 · 该问什么

## 第1步：识别"动作"

先判断用户这句话背后，真正在问的动作是哪一类。不要跳过这一步直接找词条。

常见动作有五类：
- **亏了，该不该卖**：先判断"亏"是正常波动还是买错了东西

| 两个选项选哪个 | 先看"最坏情况"和"流动性" | 机会成本、应急金、流动性、IRR |

候选词条簇只是池子，不是最终答案。下一步要从中挑。

## 第3步：挑出 3-5 个词条，并排序

从候选池里挑，不超过 5 个。排序原则：**先看哪个能让他不慌，再看哪个能让他做决定。**

- 排第一的，必须是"最该先看"的那条——它要能直接回答用户当下最急的疑问

## 第4步：每个词条写三样东西

- **一句话人话**：不超过 30 字，不用术语

## 第5步：给"最该先看"一个明确理由

- ✅ "最该先看"必须给出"为什么是它"的理由
- ✅ 输出必须让一个没学过金融的人能读完、能听懂、能带走一个问题


# 示例

## 示例1

输入：
"我买的理财亏了，要不要赶紧卖掉？"

输出：

【现象】我买的理财亏了，要不要赶紧卖掉？

【你真正在问的】不是"要不要卖"，是"这个亏是正常的波动，还是我买错了东西"。

【最该先看】浮亏 vs 实亏 —— 你现在看到的是账面数字在跌，只要没卖，它就还没变成真亏。

【再看这几条】
1. 净值型理财 —— 你买的理财早就不保本了，净值会涨也会跌，这是它的正常状态，不是"出事了" —— 它回答了"理财为什么会亏" —— 看完你能分清"正常波动"和"产品出事"
2. 最大回撤 —— 查一下这只产品历史上跌得最惨的一次是多少，现在的跌幅有没有超过历史最坏情况 —— 它回答了"这次跌得算不算狠" —— 看完你能判断"这次是不是超出常态"
3. 赎回踩踏 —— 如果很多人同时恐慌赎回，产品被迫卖资产，净值会跌得更狠，你跟着卖可能卖在最低点 —— 它回答了"别人卖会不会影响我" —— 看完你能判断"现在卖是不是在跟风"

【看完你能做的判断】
看完这几条，你能回答自己一个问题：我买的这个东西，是"暂时在跌"，还是"我当初就没搞懂它"？如果是前者，不急着卖；如果是后者，卖了也不冤，但要先搞清楚下次怎么选。

## 示例2

输入：
"我妈被推荐了一个年化8%的理财产品，说保本保息，靠谱吗？"

输出：

【现象】我妈被推荐了一个年化8%的理财产品，说保本保息。

【你真正在问的】不是"收益高不高"，是"这个'保本保息'是谁保的、拿什么保"。

【最该先看】刚性兑付 —— 资管新规之后，正规理财产品不允许承诺"保本保息"。谁说保本，谁就在说一件不合规的事。

【再看这几条】
1. 庞氏骗局 —— 年化8%不算离谱，但如果收益来源说不清，很可能是"借新还旧"，用后来人的钱付前面人的利息 —— 它回答了"高收益可能是怎么来的" —— 看完你能判断"收益来源说不说得清"
2. 非法集资 —— 看它有没有金融牌照、资金投向是否透明，没有这两样，"保本保息"就是话术 —— 它回答了"这东西合不合规" —— 看完你能判断"该不该继续听下去"
3. IRR（内部收益率） —— 如果它附带"分期返还""先返息"之类的结构，用IRR算一下真实年化，可能和宣传的8%差很远 —— 它回答了"宣传的收益是不是真的" —— 看完你能判断"真实收益大概是多少"

【看完你能做的判断】
看完这几条，你能回答自己一个问题：这个产品如果亏了，谁负责赔？如果没人能明确回答，那"保本保息"就是一句空话。


# 触发方式

用户输入一句现象描述时，直接按上述流程输出。不需要用户先说明"请用现象倒查"，也不需要用户提供额外背景。

如果用户输入的不是现象（比如是一个词、一段新闻、一个数据），回复："给我一句你遇到的现象，比如'我买的理财亏了'或'我妈被推荐了个高息产品'，我来帮你倒查该看什么。"
怎么用这个 prompt
方式一：直接复制。 把上面整段复制到 DeepSeek、Claude、Kimi、豆包任何 AI 的对话框里，然后输入你的现象，它会按格式输出。

方式二：存成文件。 保存成 现象倒查.md，发给同事或客户，他们打开文件、复制到 AI 里就能用。

方式三：放进知识库。 如果你用 ima 或其他知识库工具，把这个 prompt 设为系统指令，用户输入现象时自动触发。

一个使用细节：如果输出里提到的词条，你的词典里已经有完整版本，可以在 prompt 末尾加一句“输出后，把命中的词条名列出来”，方便用户去词典里查全文。

命名：贴合“理财投资”的领域感
“现象倒查”这个名字偏通用，不够像理财领域的术语。换个叫法：“症状倒查”——用户描述一个“症状”（理财亏了、被推荐了高息产品、听说黄金要涨），你倒查出“该查的几个词条”。这个命名来自医疗场景，普通人一听就懂，也贴合“诊断”的隐喻。

或者叫 “理财急诊台”——更口语，更有场景感。用户带着一个“急”的问题来，你给一个“分诊”结果。

我倾向 “症状倒查” 作为内部 Skill 名（放在 MCP 的工具名、知识库的条目名里），“理财急诊台” 作为面向用户的展示名（网页按钮、卡片标题）。

放进知识库 vs 放进 MCP：哪个更好
知识库适合“查”，MCP 适合“调”。 两者解决的不是同一个问题。

知识库（ima、Notion、飞书知识库这类）：用户打开一个界面，输入问题，检索、阅读。它的优势是可浏览、可收藏、可分享，适合“我想看看这个工具能干什么”的人。缺点是用户得主动打开它，有启动成本。

MCP：AI 客户端（Claude Desktop、Cursor、支持 MCP 的 IDE）在对话中自动调用你的工具。用户不需要“打开一个知识库”，他在跟 AI 聊天时，AI 发现“这个问题该查词典”，就调你的 symptom_lookup 工具。它的优势是无感、嵌入工作流，适合已经把 AI 当日常工具的人。

对“症状倒查”这个 Skill，两个都值得放，但目的不同：

放知识库：是“展示”。让投顾看到“这个词库能这么用”，它会成为一个可传播的样例。投顾可以复制 prompt、可以照着改。

放 MCP：是“调用”。让 AI 在对话里直接跑这个倒查，用户不用离开对话框。投顾在给客户写解读时，AI 顺手就把“症状”翻成了“词条清单”。

我的建议：先放知识库，再做 MCP。 因为知识库的搭建成本低、可验证“有没有人真的用”，而且它天然适合“展示 Skill 长什么样”。MCP 是给“已经信任你、想把它嵌进工作流”的人用的，是第二步。

下一个场景：Skill 05 · 该问什么
它和“症状倒查”是一对：症状倒查解决“我遇到这事该看什么”，该问什么解决“我面对这个产品该问什么”。两个加起来，覆盖普通人“防坑”的完整路径。

Skill 名（内部）：question_probe（问题探针）
展示名：“该问什么” 或 “防坑三问”

一句话说明：用户给出一个产品名或概念（“增额寿”“可转债”“某款理财”），这个 Skill 输出“你应该问销售的 3-5 个问题”，每个问题配一句“为什么重要”和“对方可能的回避话术”。

和 Skill 02 的区别：02 是“从现象倒查词条”，05 是“从产品倒推该问的问题”。02 的输出是“看什么”，05 的输出是“问什么”。02 帮用户理解，05 帮用户验证。

Skill 05 · 该问什么（question_probe）
一句话说明：用户给出一个产品名或概念，这个 Skill 输出“你应该问销售的 3-5 个问题”，每个问题配一句“为什么重要”和“对方可能的回避话术”。

【输入】
用户提供一个产品名、一个概念、或者一段销售话术。

示例输入：

“增额终身寿险”

“可转债”

“某款年化5%的银行理财”

“销售说这个保险能锁定3%复利，还送意外险”

“朋友推荐了一个基金，说过去三年年化20%”

【处理流程】
第 1 步：识别“这是哪一类东西”

先判断用户问的是哪一类产品。不同类型，该问的问题完全不同：

类型	判断依据	该问的核心
保险类	名字带“险”“寿”“年金”	锁的是什么、提前拿会怎样、保的是谁
基金类	名字带“基金”“ETF”“指数”	跟踪什么、费率多少、经理换了没
银行理财类	名字带“理财”“净值型”	投什么、历史最大回撤、能不能随时取
债券/固收类	名字带“债”“固收”	信用评级、久期、违约了怎么办
权益/股票类	名字带“股票”“权益”	估值贵不贵、靠什么赚钱、最坏情况
说不清类	用户只给了“收益”“推荐”	收益来源、牌照、谁在保
如果判断不出来，直接问用户一句：“这个东西是保险、基金、理财，还是别的？”不要猜。

第 2 步：从“类型”倒推“必问清单”

每类产品有 3-5 个“必问问题”，是这类产品最容易藏坑的地方。这些问题是通用的，不针对具体产品。

第 3 步：把通用问题“翻译”成用户能直接说出口的话

不能给用户“你应该问转股溢价率是多少”——用户不知道这个词。要翻译成：“你跟我说这个能转成股票，那现在转成股票划算，还是直接卖债划算？”

每个问题必须满足：用户能照着念出来，销售能听懂，而且这个问题让销售无法用“放心吧”糊弄过去。

第 4 步：给每个问题配“对方可能的回避话术”

这是这个 Skill 最关键的部分。用户问了一个好问题，销售可能会用一句“这个您不用担心”绕过去。提前告诉用户“对方可能会怎么绕”，用户就不会被绕过去。

第 5 步：排一个“先问哪个”的顺序

3-5 个问题，不能平铺。排第一的，必须是“如果对方答不上来，后面就不用问了”的那个问题。

【输出结构】
text
【你问的是】产品/概念名

【它属于哪一类】保险 / 基金 / 理财 / 债券 / 权益 / 说不清

【先问这一句】
问题原话 —— 为什么先问它

【再问这几句】
1. 问题原话 —— 为什么重要 —— 对方可能怎么绕
2. 问题原话 —— 为什么重要 —— 对方可能怎么绕
3. 问题原话 —— 为什么重要 —— 对方可能怎么绕

【如果对方这样回答，你要警惕】
一句总结：什么回答是“红灯”
【质量红线】
❌ 不允许给“你应该问IRR是多少”这种用户说不出口的问题

❌ 不允许超过 5 个问题

❌ 不允许只给问题、不给“为什么重要”

❌ 不允许只给“为什么重要”、不给“对方可能怎么绕”

✅ 每个问题必须是用户能照着念出口的原话

✅ 每个问题必须让销售无法用“放心吧”“这个您不用管”糊弄

✅ 必须给“红灯信号”——什么回答意味着“别继续了”

【示例 1：增额终身寿险】
输入：“增额终身寿险”

输出：

text
【你问的是】增额终身寿险

【它属于哪一类】保险

【先问这一句】
"这款产品的现金价值表能给我看一下吗？前五年如果我退保，能拿回多少？"
—— 为什么先问它：增额寿的"3%复利"说的是保额增长，不是你交的钱每年涨3%。你真正能拿回的钱看的是"现金价值"。前五年现金价值通常远低于你交的保费，这时候退保是亏本的。先看这张表，你就知道这笔钱多久不能动。

【再问这几句】
1. "您说的3%，是保额每年增长3%，还是我交的钱每年能拿到3%的收益？"
—— 为什么重要：这是销售话术里最常见的偷换概念。保额增长和你实际收益是两回事 —— 对方可能怎么绕："都是3%，一样的，您放心。"

2. "如果我一直不取，到我80岁的时候，现金价值大概是多少？"
—— 为什么重要：增额寿的收益是"前低后高"，长期持有才接近宣传的数字。问一个具体年龄的现金价值，能看出它到底划不划算 —— 对方可能怎么绕："这个要看具体情况，反正肯定比存款高。"

3. "这笔钱如果我第6年急用，能取多少？取出来之后保额会怎么变？"
—— 为什么重要：增额寿取钱的方式是"减保"，减保之后保额会下降，不是"取出来还能全额保" —— 对方可能怎么绕："可以取的，很灵活。"

4. "除了增额寿，您能不能告诉我，同样的钱放国债或者大额存单，收益大概差多少？"
—— 为什么重要：增额寿的对手不是"什么都不买"，是"买别的"。让销售自己说对比，你能听出他是不是只讲这一款的好处 —— 对方可能怎么绕："那些收益太低了，而且会降。"

【如果对方这样回答，你要警惕】
如果对方对"前五年退保拿回多少"含糊其辞、或者说"这个不用看"，直接停。一个诚实的销售会主动把现金价值表翻给你看。

输入：“某款年化5%的银行理财”

输出：

text
【你问的是】某款年化5%的银行理财

【它属于哪一类】银行理财

【先问这一句】
"这款产品过去一年的最大回撤是多少？历史上有过跌破净值的时候吗？"

【再问这几句】
1. "这5%是业绩比较基准还是预期收益率？如果是业绩比较基准，过去一年实际年化是多少？"
—— 为什么重要：业绩比较基准是"参考值"，不是承诺。实际收益可能高于也可能低于 —— 对方可能怎么绕："差不多就是这个数。"

2. "它主要投什么？债券占多少、权益占多少、有没有非标资产？"
—— 为什么重要：投什么决定了它为什么会跌。全是债券的，波动小；含权益的，波动大；含非标的，流动性可能差 —— 对方可能怎么绕："都是很稳健的资产。"

3. "如果我要用钱，赎回几天到账？有没有封闭期？"
—— 为什么重要：理财不是存款，不是随时能取。封闭期内的钱一分取不出来 —— 对方可能怎么绕："很快的，一两天。"

4. "这款产品的管理费、托管费、销售服务费分别是多少？"
—— 为什么重要：这些费用从净值里扣，你看到的是"扣完费之后"的收益，但费用高低决定了你实际拿到多少 —— 对方可能怎么绕："费用很低的，不用管。"

【如果对方这样回答，你要警惕】
如果对方一直说"这个很稳的""跟存款差不多"，却说不清最大回撤和投资方向，直接停。一个诚实的产品说明书会写清楚"不保本"，而不是用"稳"来暗示保本。
【示例 3：朋友推荐了一个基金，说过去三年年化20%】
输入：“朋友推荐了一个基金，说过去三年年化20%”

输出：

text
【你问的是】一只过去三年年化20%的基金

【它属于哪一类】基金

【先问这一句】
"这只基金现在的基金经理，是不是创造过去三年20%业绩的那个人？他管这只基金多久了？"
—— 为什么先问它：基金的业绩是"人"创造的。如果创造业绩的经理已经离职，或者这只基金是现任经理刚接手的，那"过去三年20%"跟现任经理没关系。这是买基金最常见的坑。

【再问这几句】
1. "这只基金前十大重仓股是什么？集中在哪几个行业？"
—— 为什么重要：过去三年20%，可能是因为重仓了某一个当时很火的行业。行业变了，业绩就变了。看持仓，才知道它靠什么赚的钱 —— 对方可能怎么绕："这个您不用看，看收益就行。"

2. "它过去三年的最大回撤是多少？"
—— 为什么重要：年化20%只告诉你"平均每年赚多少"，不告诉你"中间跌得多狠"。如果中间跌过40%，你拿不拿得住是另一回事 —— 对方可能怎么绕："长期看肯定是涨的。"

3. "这只基金现在规模多大？过去一年规模有没有突然暴增？"
—— 为什么重要：规模突然暴增的基金，业绩往往回落——船大了不好掉头。而且你可能是被"过去业绩"吸引进去的最后一波人 —— 对方可能怎么绕："规模大说明大家认可。"

4. "它和沪深300指数基金比，过去三年多赚了多少？扣掉管理费之后呢？"
—— 为什么重要：主动基金的管理费比指数基金高。如果它扣费之后跑不赢指数，你付了更多的钱，买了更差的结果 —— 对方可能怎么绕："它是主动管理，不一样的。"

【如果对方这样回答，你要警惕】
如果对方只反复强调"过去三年20%"，却说不清"谁在管、重仓什么、最大回撤多少"，直接停。过去业绩是最好卖的东西，也是最不能预测未来的东西。

Skill 03 · 二选一对打（duel_compare）
一句话说明：用户给出一个“A 还是 B”的选择，这个 Skill 把两个选项放进同一个决策场景里，并排对比，给出“什么条件下选 A、什么条件下选 B、什么条件下两个都别选”的分界线。

和 Skill 04 的区别：04 是“我该不该做这件事”，03 是“我该选 A 还是 B”。04 拆变量，03 比选项。03 的关键不是“罗列优缺点”，是先让用户确认“这两个选项是不是真的在同一个场景里对打”——很多时候，用户以为自己在 A 和 B 之间选，其实 A 和 B 解决的不是同一个问题。

【输入】
用户提供一个二选一的选择，口语说就行。

示例输入：

“存定期还是买银行理财？”

“买房还是继续租房？”

“买黄金还是买国债？”

“定投指数基金还是一次性买入？”

“买主动基金还是买指数基金？”

【处理流程】
第 1 步：先做“场景校验”——这两个选项，真的在同一个场景里对打吗？

这是整个 Skill 最关键、也最容易被跳过的一步。

很多用户给出的“A 还是 B”，其实两个选项解决的不是同一个问题，或者根本不在同一个决策层级上。直接对比，会得出错误的结论。

校验三问：

第一问：它们解决的是同一个问题吗？

“提前还贷 vs 买增额寿”——是。两个都是“手里有一笔闲钱，放哪里”的问题。

“买房 vs 租房”——是。两个都是“住哪里、怎么住”的问题。

“买黄金 vs 买国债”——不完全是。黄金是“抗通胀/避险”，国债是“保本吃息”，它们解决的是不同的问题，不是二选一，是可能同时配置。

“存定期 vs 买理财”——是。两个都是“低风险闲钱放哪里”。

第二问：它们的风险等级、流动性、时间期限，大致可比吗？

如果 A 是“5 年不能动”，B 是“随时能取”，它们不在同一个时间维度上，不能简单比“收益”。

如果 A 是“不保本”，B 是“保本”，它们不在同一个风险维度上，不能简单比“收益”。

第三问：用户是不是被“收益”两个字带偏了？

很多“A 还是 B”的问题，用户真正在比的只是“哪个收益高”。但收益高的那个，可能风险高、流动性差、门槛高。先问用户：除了收益，你还看重什么？

如果校验不通过，不能硬比。要告诉用户：“这两个东西不是二选一的关系，它们解决的是不同的问题。你真正该问的是______。”

第 2 步：给两个选项“放进同一个场景”

校验通过后，把 A 和 B 放进同一个用户场景里。场景要具体到“一个真实的人、一笔真实的钱、一个真实的时间”。

场景的写法：

假设你手里有 50 万，这笔钱 5 年内不用，你希望它“不亏本、能跑赢通胀”。在这个前提下，A 和 B 分别意味着什么？

场景必须包含三个要素：一笔钱、一个时间、一个目标。缺一个，对比就不成立。

第 3 步：并排对比四个维度

不要罗列一堆优缺点。只对比四个维度，每个维度一句话：

维度	A 是什么	B 是什么
最坏情况	最差会怎样	最差会怎样
流动性	急用钱时能不能取	急用钱时能不能取
收益来源	靠什么赚钱	靠什么赚钱
适合谁	什么人适合	什么人适合
“最坏情况”排在第一位，因为普通人做选择时，最容易只看收益、不看最坏情况。

第 4 步：给“分界线”，不给“哪个好”

这是和“罗列优缺点”最大的区别。不说 A 好还是 B 好，说“在什么条件下，A 赢；在什么条件下，B 赢”。

分界线的写法：

如果 ______，选 A 更合理；
如果 ______，选 B 更合理；
如果 ______，两个都别选，先做另一件事。

第三种情况最重要——很多二选一的问题，真正的答案是“两个都别选”。比如“提前还贷 vs 买增额寿”，如果应急金不够，两个都别做，先存应急金。

第 5 步：给一个“试算”动作

用户看完分界线，可能还是不确定自己属于哪种情况。给一个简单的试算，让用户自己算出一个数，用这个数对号入座。

试算的写法：

算一下：你的房贷利率是 ______%，你能稳定赚到的收益是 ______%。如果前者大于后者，选 A；如果后者大于前者，选 B。

试算必须是用户今天能算出来的，不是“需要专业知识才能算”的。

设计说明：三个改动，解决三个问题
改动一：搜索框从“搜词”变成“搜任何东西”。

原来的搜索框只能搜词。但用户真正的起点，往往不是“一个词”，是“一句话”或“一段内容”。所以搜索框的占位符要改成“输入一个词、一句话，或者直接贴一段新闻”。贴进来之后，系统自动判断：是词就跳词条，是现象就走症状倒查，是内容就走概念串联。 用户不用先选“我要用哪个功能”，搜索框本身就是入口。

改动二：首页从“平铺词条”变成“五个入口 + 折叠的词条区”。

平铺词条的问题不是“乱”，是“用户不知道从哪开始” 。他看到一个不认识的词，才会点；但他真正的问题往往是“我遇到个事，不知道该搜什么”。所以首页第一屏放五个“你可能正遇到……”的卡片，对应五个 Skill。词条区不删，但折叠起来，放在下面，给“已经知道要搜什么”的用户用。这样既照顾了“不知道搜什么”的人，也保留了“查词”的路径。

改动三：词条详情页从“只展示相关内容”变成“场景入口 + 下一步动作”。

原来的详情页只有“相关词条”，是死路——看完这个词，用户不知道下一步做什么。加两块：“这个词常出现在这些场景里” （把词条和五个 Skill 打通，用户看到“我买的理财亏了→浮亏vs实亏”，就知道这个词在什么情况下用得上）+ “想更深入？” （直接给两个按钮，跳转到对应的 Skill）。词条不再是终点，是下一个动作的起点。

一个要你定的问题
首页那五个入口卡片，是只放五个 Skill，还是每个 Skill 下面再列 2-3 个“常见场景” ？前者更干净，后者更“像用户的话”。我倾向后者——卡片标题用用户的话（“我买的理财亏了”），副标题才是 Skill 名（“症状倒查”）。这样用户看到的是自己的问题，不是你的工具名。

你确认这个结构，我可以把它做成可运行的 HTML 原型，或者先把五个入口的卡片文案逐字写出来。

那如果我按照后者去做的话，你帮我想想你刚刚说的时候，用户直接在搜索框里面搜东西，我担心用户不会用或者我担心我的。嗯，没法很好的实现。嗯，就是我不知道我们用这个skill的时候涉及到这种场景会不会一定要调用AI。如果是一定要调用AI那确实我的成本会大很多，然后关于订阅这个事情。我并不觉得这个事情解决了用户的一个强关系，它的使用可能发生在c端用户呃， b端用户那里。然后是我们这个里面其实倒是有一个热点的入口，就是在搜索下面已经有了个今日热词，我会收取5条在中国市场上发生比较热点的话题，用户点击进去我会基于这个话题拿到热词然后去做分析。这个是相对对于来说跟时行情比较近的，然后其他几个场景我觉得很重要，但是没有想好怎么展示。
你担心的三件事，我分开说：搜索框要不要调 AI、订阅是不是弱关系、其余场景怎么展示。结论先给——搜索框不要调 AI，订阅不要卖给 C 端，其余场景不做成“入口”，做成“搜索框的三种变形”。

一、搜索框：不做“智能搜索”，做“分流器”
你担心“用户不会用”和“调用 AI 成本大”，这两个担心是同一个问题的两面。解法不是让搜索框更聪明，是让搜索框只做它便宜又可靠的事：判断你贴进来的是什么，然后把你送到该去的地方。

搜索框只做三件事，零 AI 成本：

第一件，贴进来的是“一个词” → 直接查本地词库，跳词条详情页。这是纯前端匹配，零成本。

第二件，贴进来的是“一句话（现象）” → 不调 AI，用关键词规则匹配。比如句子里出现“亏了、跌了、被套”，就推“浮亏vs实亏、净值型理财、最大回撤”这几个词条；出现“推荐、保本、高息、年化”，就推“刚性兑付、庞氏骗局、非法集资、IRR”；出现“要不要、该不该”，就推“决策拼图”的入口。这不是 AI，是一张“现象→词条簇”的映射表，你写 30-50 条规则，覆盖 80% 的日常表达。用户点进词条后，详情页底部再给一个“用 AI 深入分析”的按钮——AI 在第二步才出现，而且由用户主动触发。

第三件，贴进来的是“一段内容（超过两行）” → 这才是需要 AI 的场景。但也不要在搜索框里直接跑，而是把内容带进“概念串联”页面，让用户在页面上点“生成”。这样成本可控、用户有预期，而且生成结果可以缓存。

一句话原则：搜索框只负责“分类”，不负责“生成”。 分类零成本，生成才花钱，而且生成永远由用户主动点击触发。

至于“用户不会用”的担心——占位符要写三个例子，不是写“请输入”。占位符写：“试试：我买的理财亏了 / 增额寿 / 贴一段新闻”。下面再加一行小字：“贴词查词条，贴句子找方向，贴内容做解读。”用户看一眼就知道三种用法。

二、订阅：C 端不卖订阅，卖“一次性交付”或“按次”
你说得对，订阅对 C 端是弱关系——普通人不会每月为“一个词典”付费。词典是“有事才来，没事不来”的产品，订阅制和它的使用频率是错配的。

C 端不要做订阅，做两种轻模式：

第一种，按次付费。 免费查词条、免费看“一句话人话”。但“贴一段内容生成六屏叙事”“生成该问的问题清单”这类重动作，按次收费或打包成“10 次卡”。这符合用户“有事才用”的行为——他不需要承诺每月付费，只需要在需要的时候买一次。

第二种，一次性交付。 比如“五个 Skill 的 prompt 合集”卖 9.9 或 19.9，买断，永久用。这不是订阅，是“买一套工具”。用户买的是“以后遇到事我知道怎么拆”，不是“每月来一次”。

订阅留给 B 端。 投顾是“每天都要产出内容”的人，订阅制和他的使用频率是匹配的。B 端订阅卖的不是“词典”，是“品牌化交付 + 合规留痕 + 稳定产能” 。这个关系是强关系——他每天都在用，停掉就影响工作。定价按席位/按月，合理。

三、其余场景怎么展示：不做“入口”，做“搜索框的三种状态”
你已经有“今日热词”了，这是很好的“内容驱动入口” ——用户不是带着问题来，是被热点吸引来。这个位置保留，它解决“用户不知道自己需要什么”的问题。

其余几个场景（概念串联、二选一对打、决策拼图、该问什么），不要做成首页的并列卡片。并列五个入口，用户会懵：我到底该点哪个？

更好的做法：把它们做成“搜索框在用户输入之后自然长出来的选项”。

用户贴了一段内容 → 搜索框下方出现：“要不要用『概念串联』把它拆成六屏叙事？”（一个按钮）

用户输入“提前还贷还是买增额寿” → 搜索框下方出现：“这是在两个选项里选？用『二选一对打』帮你比。”（一个按钮）

用户输入“该不该给孩子存教育金” → 出现：“用『决策拼图』拆成变量？”

用户输入“增额寿” → 词条详情页底部出现：“用『该问什么』生成提问清单？”

核心逻辑：场景不是“入口”，是“在用户表达出意图之后，系统递上的下一步”。 用户不需要预先知道有五个 Skill，他只需要在输入之后，看到一个“要不要更进一步”的按钮。这样既解决了“不知道怎么展示”，也避免了“五个并列入口没人点”的问题。

唯一例外是“今日热词”。 它不需要用户先输入，它是“内容主动找用户”。所以它放在搜索框下面、五个 Skill 之上，作为一个独立的“今日有什么值得看”的区块。

上一版的问题不在结构，在我一直在“给你搭系统”，没有回答你真正卡住的那个点。

你卡住的不是“首页怎么排版”。你卡住的是：一个查词条进来的人，凭什么会去做“概念串联”“二选一对打”这些更重的动作？ 如果他不会，那五个 Skill 就是五个没人点的按钮；如果他会，你就不需要费这么大劲设计入口。

先把这个想清楚，页面才有得谈。

第一件事：查词条的人，和做组合的人，是两种人。

查词条的人，目标是“搞清楚一个词”。他路径短、目的明确，看完就走。你硬在他看完词条后塞一个“用决策拼图拆一下”，他不会点——他没那个需求，你只是在打扰他。

做组合的人，目标是“搞定一段内容或一个决定”。他不会从“查词条”进来，他从“我手里有个东西要处理”进来。

这两条路径不该在首页被强行合并。 首页的作用不是“让所有人都看到所有功能”，是让两种人各自找到自己的入口，互不打扰。

第二件事：五个 Skill 里，只有一个适合放在首页当入口。

“今日热词”已经证明了一件事：用户愿意为“今天发生了什么”点进去，不愿意为“我可以用什么工具”点进去。 热词是内容驱动，不是工具驱动。

顺着这个逻辑，五个 Skill 里最适合当首页入口的，不是“概念串联”（它太重，需要用户主动贴内容），是“症状倒查”——因为它的触发方式和热词一样：用户带着一个具体的、热的、正在困扰他的事来（“我买的理财亏了”）。它不需要用户先理解工具，它接的是用户已经在焦虑的那句话。
